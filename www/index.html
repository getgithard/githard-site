Your repo's been soft long enough.

GitHard is a Claude Code plugin that sets up your GitHub org and repos the way you'd want them a year from now, then helps you run them. Tank handles the drills: rulesets, pinned Actions, fork PRs read before they run, and a reply for every contributor.

The drills.

    
Each drill is a skill Claude loads when your request needs it. Ask for what you want in your own words. Tank works out which drill fits.

    

      
repo-setup
Community files, a ruleset that keeps main PR-only, DCO, Dependabot grouped monthly, Actions pinned to SHAs. Audits an existing repo against the same list.

      
fork-pr-safety
Reads a stranger's full diff before their CI runs, and approves only the commit it read. Never pushes to their branch.

      
contributors
A welcome for every claim, a reply for every outside PR, a person (not a stale bot) for the quiet ones, and an AI policy.

      
writing
READMEs, release notes and replies that sound like a person wrote them. Uses your project's style guide if you have one.

      
using-githard
The front door. Sends your request to the right drill, and tells you straight when that drill isn't built yet.

    

    
Still in training

    

      
issues-and-roadmap
Milestones, a board, and starter issues people actually finish.

      
merging
Merge when green, one at a time, without burning the API limit.

      
releases
Cut, verify and publish, then everything a release leaves behind.

      
docs-honesty
Docs that only say what shipped.

      
security-baseline
OpenSSF Scorecard, secrets, signed releases.

      
org-setup
Profile README, the .github repo, a verified domain.

      
growth
Getting seen without spamming strangers.

      
save-point
A handoff file so the next session picks up where this one stopped.

    

  






  

    
Tank's tough, not reckless.

    
Some things GitHard won't do, however nicely you ask.

    
    
      
  • Push to a contributor's branch. It asks them to click Update branch instead.
    • 
      
  • Pass off its own approval as a human review.
    • 
      
  • Open "try our tool" issues on strangers' repos.
    • 
      
  • Contribute where a project's AI policy says no.
    • 
      
  • Pick your license, change your ruleset, or spend your money without asking.
