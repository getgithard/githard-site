Your repo's first day of boot camp.

Most repos get set up once, in a hurry, and never looked at again. You know the signs: main takes a direct push, Actions are pinned to a tag someone can move, a fork PR's CI got approved without anyone reading the diff, and someone claimed an issue in September and is still waiting for a reply.

GitHard is a Claude Code plugin that fixes those, and then keeps them fixed. It's fifteen skills. You ask in your own words, "set this repo up properly" or "can I approve CI on this fork PR?", and Claude loads the skill that fits. There's no server and no bot: it works through your own Claude Code session and your own gh login.

What it does on day one

Point it at a repo, new or ten years old, and it audits it against one list: community files, a ruleset that keeps main PR-only, DCO, Dependabot grouped monthly, every Action pinned to a commit SHA, secret scanning with push protection. Then it fixes what you say yes to. The same goes for your org: its profile and default community files, plus the settings only an owner can change, such as 2FA for everyone, handed to you to click.

After that, it helps you run the place. It reads a stranger's whole diff before their CI runs, and approves only the commit it read. It merges when the required checks pass on the commit that was tested, one PR at a time. It drafts releases with checksums and build attestations, and checks them before anyone publishes. It writes docs that only describe what shipped, and it finds every claim, PR and issue that's still waiting on you.

What it won't do

Push to a contributor's branch. Pass off its own approval as a human review. Open "try our tool" issues on strangers' repos. Contribute where a project's AI policy says no. Pick your licence, change your ruleset or spend your money without asking you first.

We ran it on itself first

First, GitHard took keyparity, a small Bun CLI, from an empty org to a published, attested release on npm with an OpenSSF Best Practices badge. It found eight gaps in itself along the way, and each one is fixed.

For this release we pointed its own advice at its own scripts. Every script now runs in CI against stand-ins for GitHub, with 90% statement coverage and a fuzz of every argument list. That turned up four real bugs. The worst: the merge script took a failed check from outside GitHub Actions for a download flake, and spent both of its reruns on nothing before it gave up. A security review of every script and workflow found four more holes, and those are closed too. The release notes list each one.

Every skill ships with evals that run with the plugin and without it, so you can see what GitHard adds and where Claude already does fine on its own. They're in the repo, and the scoreboard has the numbers.

Try it on one repo

/plugin marketplace add getgithard/githard
/plugin install githard@githard

Then ask it to audit a repo you've been meaning to tidy. If it gets something wrong, or misses something your project needs, tell us in Discussions. That's the most useful thing you can do for it right now.
